# Финальное ТЗ: доработка макроса выбора режима поставки (CIP / DDP / CIP&DDP)

## Зафиксированные решения (по комментариям)

1. Dropdown должен работать **для всех** (не только Cisco).
2. В режиме `CIP&DDP` используется **тот же самый исходник**, выбранный один раз.
3. В отчёте для комбинированного режима добавляется пометка `CIP&DDP` (например, в названии в строке отчёта в конце).
4. Логика старого checkbox не меняется принудительно; если dropdown пустой — режим по умолчанию `CIP`.

## Анализ образцов (CIP vs DDP)

На тестовых образцах подтверждено:
- CIP-выход использует лист `Cisco`.
- DDP-выход использует лист `Specification`.
- DDP-шаблон содержит дополнительные поля (`Intercompany margin`, `Invoice Price CIP Tashkent`) и отличается по структуре/формулам.

## Что изменить в макросе

### 1) UI (лист `MACROS`)
Добавить dropdown рядом с текущими параметрами (после `vendor`, перед `comments to spec name`) со значениями:
- `CIP`
- `DDP`
- `CIP&DDP`

Если не выбрано значение — использовать `CIP`.

### 2) Поведение кнопки GO

Единая логика выбора режима:
- `CIP` → запуск стандартной ветки (как сейчас работало при обычном запуске).
- `DDP` → запуск DDP-ветки/шаблона, выходной файл с суффиксом `_DDP`.
- `CIP&DDP` → последовательный запуск двух веток на одном исходнике:
  1) CIP-файл,
  2) DDP-файл с `_DDP`.

Важно: файл-исходник запрашивается **один раз**.

### 3) Именование файлов

- Базовое имя: как сейчас (`SpecName`).
- CIP: `SpecName.xlsx`
- DDP: `SpecName_DDP.xlsx`
- CIP&DDP: оба файла одновременно.

### 4) Запись в отчёт

Для комбинированного режима (`CIP&DDP`) в строке отчёта добавлять маркер `CIP&DDP` в конце названия (или в отдельной колонке, если в файле отчёта есть выделенное поле режима).

Минимально обязательное условие: маркер `CIP&DDP` должен присутствовать в строке отчёта для этого запуска.

## Рекомендуемая техническая реализация

1. Вынести чтение режима в отдельную функцию (например, `GetDeliveryMode`):
   - читает значение dropdown,
   - возвращает `CIP`, если пусто/невалидно.
2. В обработчике GO:
   - открыть исходник один раз,
   - в зависимости от режима вызвать:
     - `RunCIP`
     - `RunDDP`
     - или оба подряд.
3. В процедуре сохранения добавить параметр режима/суффикса:
   - для DDP добавлять `_DDP`.
4. В процедуре записи отчёта:
   - при `CIP&DDP` добавлять `..._CIP&DDP` (или аналогичный маркер в поле комментария/имени).

## Критерии приёмки

1. Dropdown отображается на `MACROS`, выбор сохраняется и читается макросом.
2. `CIP` выдаёт тот же результат, что текущий стандартный запуск.
3. `DDP` выдаёт DDP-шаблон и имя с `_DDP`.
4. `CIP&DDP` за один запуск создаёт два файла из одного исходника.
5. В отчёте строка комбинированного запуска содержит `CIP&DDP`.
